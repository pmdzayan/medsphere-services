# F0.11 Sprint Report: Personal Privacy and Language Settings

**Status:** Implemented and locally verified on `cto/frontend-foundation`

**Dependency:** F0.10 tenant audit workspace and the mounted S0.3 current-user
and localization contracts

## Objective

Replace the disabled Settings navigation item with a premium, authenticated
workspace backed only by the accepted current-user privacy and localization
APIs. Preserve signed identity context, strict response validation, same-origin
mutation protection, and honest UI behavior where the backend contract does not
expose a current value.

## Contract audit decision

The S0.5 inventory service remains runtime-gated and exposes no accepted
production HTTP controller. Connecting the existing inventory preview to an
invented route would be false completion. Task 11 therefore uses the next
mounted accepted contracts:

| Method  | Backend route             | Frontend BFF route        |
| ------- | ------------------------- | ------------------------- |
| `GET`   | `/users/me/privacy`       | `/api/settings/privacy`   |
| `PATCH` | `/users/me/privacy`       | `/api/settings/privacy`   |
| `GET`   | `/localization/languages` | `/api/settings/languages` |
| `PATCH` | `/users/me/language`      | `/api/settings/language`  |

## Delivered

- Added an authenticated `/settings` route and enabled Settings navigation.
- Added a responsive Emerald Intelligence settings workspace with read-only
  signed identity context, five privacy controls, supported languages, loading,
  failure, unsaved, reset, saving, and confirmation states.
- Sends only privacy fields changed by the user rather than rewriting unrelated
  preferences.
- Keeps identity, tenant, membership, and credentials outside mutation bodies.
- Rejects cross-origin writes before reading or forwarding access credentials.
- Validates exact privacy, language-list, language-request, and language-response
  contracts. Unknown fields, unsupported language codes, duplicate languages,
  empty patches, and malformed successful upstream responses fail closed.
- Uses `Cache-Control: no-store` for every settings response.
- Clearly states that the accepted API can update preferred language but does
  not expose the currently stored value. The frontend does not guess or present
  a default as saved state.
- Reuses the existing authenticated API refresh-and-retry client.

## Security and privacy boundary

- The backend derives the user from the verified access token. The BFF never
  accepts a user, membership, tenant, role, or permission identifier.
- Personal preference responses are constrained to five reviewed booleans.
- Supported language metadata is constrained to the accepted `en`, `hi`, `ta`,
  `te`, and `kn` vocabulary with bounded unique display names.
- The read-only identity summary comes from the signed HTTP-only session profile.
- No patient, clinical, prescription, or medicine data is introduced.
- No database schema or migration change is required.
