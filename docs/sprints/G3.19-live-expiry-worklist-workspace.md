# G3.19 Sprint Contract: Live Expiry Worklist Workspace

**Status:** Implemented; exact-head CI and CTO acceptance required

## Objective

Connect the accepted G3.18 assigned-provider physical batch expiry read to a
live, read-only operational workspace.

## Accepted boundary

The workspace:

1. loads only providers assigned to the authenticated membership;
2. supports fixed 7, 30, 60, and 90 day horizons plus bounded pagination;
3. uses a strict same-origin BFF that forwards only provider, horizon, limit,
   and offset;
4. validates exact response shape, quantities, timestamps, horizon correlation,
   and deterministic expiry/batch ordering;
5. renders medicine, listing, batch, expiry, version-backed physical, held, and
   available evidence; and
6. labels all metrics as current-page values and exposes server observation and
   horizon timestamps.

## Explicit exclusions

- expiry reconciliation, quarantine, release, disposal, return, recall,
  transfer, adjustment, or any other mutation;
- risk scores, warnings, alerts, notifications, forecasting, or analytics;
- patient, prescription, clinical, supplier, payment, or delivery data; and
- backend, database, permission, audit, or worker changes.

## Acceptance evidence

Acceptance requires contract, BFF negative, API-client, workspace loading,
empty/access, horizon and pagination tests, full web tests, type check, lint,
production build, formatting, architecture checks, exact-head CI, and
synchronized governance records.
