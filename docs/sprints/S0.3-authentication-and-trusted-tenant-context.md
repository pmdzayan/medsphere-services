# S0.3 Sprint Specification: Authentication and Trusted Tenant Context

**Owner:** ChatGPT / Codex (CTO and large-task implementer)

**Status:** ADR accepted; implementation and verification in progress

**Dependency:** S0.2 Reproducible Database Baseline accepted and merged

## Objective

Replace the current authentication prototype with a deny-by-default, production-oriented identity boundary that derives tenant context from an active global-user membership, provides securely revocable sessions, and exposes only the routes accepted for this sprint.

## Repository evidence

The design is based on direct review of the current repository:

- `apps/auth-service/src/app.module.ts` does not import `AuthModule`.
- `apps/auth-service/src/auth/jwt.strategy.ts` is empty.
- Identity/token interfaces and the roles guard are empty.
- `AuthModule` accepts `JWT_SECRET` with `fallback-secret`.
- Access and refresh tokens use the same JWT service and validation rules.
- `UserSession.refreshToken` stores the full refresh credential.
- Refresh rotation revokes then creates in separate operations.
- Login and registration accept tenant UUIDs from the client.
- `CurrentUserId` falls back to `x-user-id`.
- Logout-all accepts the target user ID in the route.
- Most controllers have no authentication guard; provider routes use a zero UUID tenant.
- RBAC and audit queries are not yet tenant-safe.
- The API gateway currently exposes only health and does not provide an accepted security boundary.
- Authentication tests are mock-heavy unit tests and do not validate real JWT strategy, PostgreSQL rotation, replay, concurrency, or cross-tenant behavior.

## Scope

### Architecture and documentation

- Adopt ADR-003 after review.
- Add the Security Bible authentication/session chapter.
- Add the Backend Bible identity module contract.
- Add a threat model and security test matrix.
- Update the Database Bible, roadmap status, project status, ADR index, and AI handoff.

### Database

- Add `MembershipStatus` with at least `PENDING`, `ACTIVE`, `SUSPENDED`, and `REVOKED`.
- Add `TenantMembership` as the authoritative global-user-to-tenant relationship.
- Backfill one membership for every current user/tenant association.
- Make email identity global and case-insensitive using PostgreSQL `citext` plus a unique constraint.
- Add a tenant-controlled self-registration flag defaulting to false.
- Replace raw refresh-token storage with a peppered HMAC digest.
- Extend session state to distinguish active, rotated, revoked, compromised, and expired credentials.
- Add session family, membership, replacement, idle expiry, absolute expiry, last-used, revoked-at, and revocation-reason fields.
- Add query-driven indexes for active membership validation, session-family revocation, user session revocation, and expiry cleanup.
- Preserve foreign-key restrictions and document deletion/retention behavior.
- Deliberately invalidate legacy prototype sessions during migration; never attempt to retain raw-token compatibility.
- Add a migration preflight that aborts without exposing PII if case-normalized duplicate emails exist.

### Authentication configuration

- Add a typed, fail-fast auth configuration provider.
- Require base64-encoded RS256 private/public keys, issuer, audience, key ID, access TTL, refresh idle TTL, refresh absolute TTL, and refresh-token HMAC pepper.
- Validate integer ranges and key material during startup.
- Provide development key-generation instructions without committing keys.
- Remove all fallback secrets and magic TTLs.

### Tokens and sessions

- Issue minimal RS256 access JWTs with explicit token type and strict validation.
- Generate opaque refresh credentials with at least 256 bits of CSPRNG entropy.
- Store only the HMAC digest of refresh credentials.
- Use constant-time digest comparison.
- Rotate refresh credentials in a serializable transaction with bounded retry for Prisma transaction conflicts.
- Detect reuse of rotated credentials and revoke the active session family.
- Validate user, membership, tenant, and session status on access and refresh.
- Revoke current/all sessions from authenticated self context only.
- Do not decode unverified tokens as an authorization input.

### Request identity and route boundary

- Introduce one readonly `AuthenticatedIdentity` type containing user, membership, tenant, and session IDs.
- Implement `JwtStrategy` and a global deny-by-default guard with shared public metadata.
- Replace overlapping current-user decorators with one typed decorator; remove all header fallbacks.
- Add `AuthModule` to the application root.
- Keep health, language metadata, login, refresh, and policy-allowed registration public.
- Unmount unaccepted RBAC, audit, provider, provider-verification, product, and inventory controllers until their dependent sprints repair tenant and permission boundaries.
- Keep API-gateway changes limited to the accepted modular-monolith hosting direction; do not create a new microservice.

### APIs

Planned accepted endpoints:

| Method | Path                 | Access         | Tenant source                            | Purpose                              |
| ------ | -------------------- | -------------- | ---------------------------------------- | ------------------------------------ |
| POST   | `/auth/login`        | Public/limited | Resolved tenant slug + active membership | Create an authenticated session      |
| POST   | `/auth/refresh`      | Public/limited | Stored session membership                | Rotate credential and access token   |
| POST   | `/auth/register`     | Public/limited | Resolved tenant slug with policy         | Create pending identity/membership   |
| POST   | `/auth/logout`       | Authenticated  | Verified request identity                | Revoke current session family        |
| POST   | `/auth/logout-all`   | Authenticated  | Verified request identity                | Revoke all sessions for current user |
| GET    | `/users/me/privacy`  | Authenticated  | Verified request identity                | Read own privacy settings            |
| PATCH  | `/users/me/privacy`  | Authenticated  | Verified request identity                | Update own privacy settings          |
| PATCH  | `/users/me/language` | Authenticated  | Verified request identity                | Update own language                  |

Every accepted endpoint must have typed DTOs, UUID/slug/email validation, response DTOs, consistent error envelopes, OpenAPI metadata, rate-limit policy, and tests. No endpoint accepts an authoritative user, membership, or tenant ID from the client.

### Validation and password handling

- Normalize tenant slugs and emails consistently.
- Use generic login and registration responses to reduce enumeration.
- Permit passphrases and Unicode; do not add composition rules.
- Enforce a 15-character minimum while MFA is unavailable and a safe maximum of at least 64 characters.
- Configure Argon2id explicitly, benchmark it in the supported environment, and support future rehash-on-login.
- Bound all strings, including names, user agents, device labels, and token inputs.
- Reject unexpected request fields through the shared validation pipe.

### Logging and audit seam

- Record structured events for login success/failure, session creation, refresh, replay detection, logout, logout-all, and policy denial.
- Use IDs or a nonreversible correlation value; never log email where a user ID is available.
- Never log passwords, access tokens, refresh credentials, token digests, private keys, authorization headers, or request bodies containing credentials.
- Define an explicit authentication-security-event contract for S0.4 durable audit integration.
- Do not claim application logs satisfy the final audit requirement.

## Threat model

| Threat                               | Required control                                                    | Required evidence                      |
| ------------------------------------ | ------------------------------------------------------------------- | -------------------------------------- |
| Forged JWT or algorithm confusion    | RS256 allowlist, strict key/issuer/audience/type validation         | Negative token tests                   |
| Access token used after logout       | Active session lookup on every request                              | API integration test                   |
| Client tenant impersonation          | Membership-derived tenant context; no tenant header fallback        | Cross-tenant negative tests            |
| Refresh-token database disclosure    | HMAC-only storage with independent pepper                           | Database assertion test                |
| Refresh replay                       | Single-use rotation, family linkage, family revocation              | Sequential and concurrent replay tests |
| Concurrent double refresh            | Serializable transaction and conflict retry                         | PostgreSQL concurrency test            |
| User/account enumeration             | Generic errors and bounded response behavior                        | API response tests                     |
| Credential guessing                  | Per-IP and per-account throttling without logging credentials       | Rate-limit tests                       |
| Session fixation/stale privilege     | New session IDs on login/rotation and membership/session validation | Session lifecycle tests                |
| Inactive user, membership, or tenant | Server-side chain validation on every protected request             | Status matrix tests                    |
| Cross-token substitution             | Access JWT only; refresh credential is opaque; explicit token type  | Negative token tests                   |
| Secret disclosure through logs       | Redaction and security-event allowlist                              | Log-capture tests                      |
| Unaccepted prototype endpoints       | Modules not mounted                                                 | Route inventory/API tests              |

### CTO review increment — HTTP security boundary

The S0.3 review adds application-level HTTP evidence without declaring the
sprint accepted. Production bootstrap and the test application now share one
filter, validation, and OpenAPI configuration function. The assembled
application test proves public allowlisting, deny-by-default 401 behavior,
algorithm-substitution rejection, server-derived self context, live session
revocation, supported language availability, and 404 responses for every
unaccepted prototype module. PostgreSQL and Redis adapter behavior remains
covered by their dedicated integration suites.

The review also centralizes access-token header/claim validation and fixes an
account-throttling bypass in which casing or surrounding whitespace could
create multiple pre-validation rate-limit buckets for the same normalized
tenant/email locator.

### Infrastructure test gate

PostgreSQL and Redis authentication integration suites are gated behind the
`RUN_AUTH_INFRASTRUCTURE_TESTS` environment variable.

- **Local development:** `pnpm test` skips infrastructure suites by default.
  A developer `.env` containing `DATABASE_URL` or `REDIS_CLUSTER_URL` does not
  accidentally activate them.
- **CI:** The workflow sets `RUN_AUTH_INFRASTRUCTURE_TESTS: "true"` and provides
  real PostgreSQL 16 and Redis 7 service containers.
- **Deliberate local execution:** Set `RUN_AUTH_INFRASTRUCTURE_TESTS=true` and
  ensure PostgreSQL 16 and/or Redis 7 are running and reachable via the
  configured `DATABASE_URL` and `REDIS_CLUSTER_URL`.

The gate is implemented in `apps/auth-service/src/auth/testing/infrastructure-test-gate.ts`.
Future authentication infrastructure suites must reuse
`isInfrastructureTestEnabled` and `requireEnv`.

## Completion criteria

- ADR-003 is accepted and all affected Development Bible volumes are updated.
- Clean and upgrade-path migrations pass without schema drift.
- Legacy raw refresh sessions are invalidated and no raw refresh credential is persisted.
- Authentication fails startup without valid key/configuration material.
- Every non-public accepted route is denied without a valid, active session-backed access token.
- Tenant context can only come from an active membership chain.
- Inactive/deleted user, inactive membership, inactive/deleted tenant, revoked/expired session, wrong issuer/audience/type/algorithm, and mismatched claims are rejected.
- Rotation is atomic; replay and concurrent refresh behavior are proven against PostgreSQL.
- Logout and logout-all are self-only and invalidate server-side sessions.
- Unaccepted prototype controllers are not reachable.
- Authentication inputs are validated, bounded, rate-limited, and documented.
- Logs and error responses contain no credential material or unnecessary identity disclosure.
- Format, database verification, lint, test, build, workflow syntax, diff review, and CI pass.
- CTO completes final architecture and code review before the PR is marked ready or merged.
