# G3.3 Sprint Contract: Provider Reservation Operations

**Status:** Implementation and local non-infrastructure verification complete;
exact-commit PostgreSQL CI and review pending

**Accepted base:** `3249f8ac46f043473630a473aea0e49ff72d4a5d`

## Objective

Prepare the first accepted medicine-reservation operations boundary for assigned
provider staff without inventing patient-consent or system-worker authority.

## Accepted scope

- permission-protected provider reservation list and detail reads;
- operational responses that omit patient identity and free-text notes;
- staff transitions for `CONFIRM`, `READY`, `COMPLETE`, and `CANCEL`;
- live provider assignment before every command receipt lookup and replay;
- expected-version, tenant-scoped idempotency, and canonical command hashes;
- serializable stock consumption or hold release with atomic typed audit evidence;
- completion movements linked to the reservation command hash;
- clean and populated upgrade verification for the two G3.3 permissions;
- unit, HTTP-boundary, and real PostgreSQL atomicity/concurrency tests.

## Explicitly blocked

- patient or public reservation creation, because no accepted provider-patient
  relationship and consent policy exists;
- user-triggered `EXPIRE`, because expiry requires a dedicated tenant-scoped
  system-worker contract;
- patient identity, contact details, clinical data, or free-text notes in the
  inventory operations response;
- delivery, payment, controlled-medicine, supplier, marketplace, or clinical work;
- frontend integration before this exact backend contract is accepted.

## HTTP contracts

- `GET /inventory/providers/:providerId/reservations`
- `GET /inventory/providers/:providerId/reservations/:reservationId`
- `POST /inventory/providers/:providerId/reservations/:reservationId/transitions`

Reads require `inventory.reservations.read`; transitions require
`inventory.reservations.manage`. Missing provider assignment and missing
reservation use the same not-found concealment boundary. Read responses use
`Cache-Control: private, no-store`.

## Completion criteria

1. Clean PostgreSQL migration, status, and drift verification pass.
2. Populated S0.3-through-G3.3 upgrade verification passes.
3. Infrastructure tests execute with zero skips and prove atomic completion,
   unauthorized replay concealment, and one-winner concurrency.
4. Formatting, lint, tests, build, and production dependency audit pass.
5. Exact-commit pull-request CI, review, and merge acceptance pass.

G3.3 does not complete Gate 3. Transfers, returns, damage, quarantine/recall,
expiry-worker behavior, safe creation, and live frontend integration remain
separate bounded sprints.
