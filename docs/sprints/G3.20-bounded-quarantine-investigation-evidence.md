# G3.20 Sprint Contract: Bounded Quarantine Investigation Evidence

**Status:** Implemented; exact-head CI and CTO acceptance required

## Objective

Expose immutable one-way batch quarantine records as a bounded, read-only
assigned-provider evidence feed without exposing command secrets or creating a
release, recall, approval, or disposition workflow.

## Accepted boundary

`GET /inventory/providers/:providerId/quarantine-evidence`:

1. requires `inventory.stock.read` and an active same-tenant provider assignment;
2. accepts only bounded limit/offset pagination;
3. reads immutable quarantine records in stable `occurredAt DESC, id DESC` order;
4. returns opaque record, inventory, product, batch, and actor-membership UUIDs;
5. returns medicine/listing/batch labels, current batch status, bounded reason
   code, physical quantity, reservation/released-unit counts, resulting batch
   version, and occurrence timestamp;
6. excludes idempotency keys, command hashes, request metadata, contact data,
   and user names; and
7. uses a private no-store response and conceals unassigned providers as 404.

## Explicit exclusions

- quarantine release, recall, disposal, return, refund, approval, reversal,
  correction, or any mutation;
- free-text incident notes, attachments, supplier claims, notifications,
  analytics, risk scoring, or regulatory assertions;
- patient, prescription, clinical, payment, or delivery data; and
- schema, migration, permission-catalogue, audit, or worker changes.

## Acceptance evidence

Acceptance requires DTO, controller, service concealment/secret-exclusion, and
real PostgreSQL assigned-provider isolation tests with zero infrastructure skips
in CI, full tests, formatting, lint, build, database gates, exact-head CI, and
synchronized governance records.
