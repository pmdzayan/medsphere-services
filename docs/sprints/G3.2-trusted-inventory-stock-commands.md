## Objective

Prepare the first Gate 3 write boundary for acceptance for assigned provider staff:
versioned inventory-listing configuration, new-batch receipt, and stock-count
adjustment. Preserve ADR-005 stock integrity and ADR-007 provider authority
without mounting reservation, transfer, return, or patient workflows.

## Accepted HTTP candidates

- `PUT /inventory/providers/:providerId/products/:productId`
- `POST /inventory/providers/:providerId/products/:productId/batches`
- `POST /inventory/providers/:providerId/batches/:batchId/adjustments`

Each route requires verified JWT identity, a migration-owned permission, and a
live `MembershipProviderAccess` assignment. Provider, tenant, actor, membership,
and user headers or body fields never establish authority.

## Integrity contract

- Commands execute in serializable transactions with bounded retry.
- Listing updates and batch adjustments use expected versions.
- Every command uses a tenant-scoped idempotency key and canonical command hash.
- Replays are resolved only after live provider authorization.
- Batch is the quantity authority and adjustments cannot consume held stock.
- Stock movements remain append-only and exact arithmetic is database checked.
- Audit events are written atomically with their protected mutations.
- Unknown request fields and malformed UUID, date, integer, decimal, and bounded
  text inputs fail at the HTTP boundary.

## Migration contract

The forward migration adds an optional, constrained command hash to historical
stock movements and migration-owned permissions for listing management, stock
receipt, and stock adjustment. Existing historical ledger rows remain valid;
all newly exposed commands write a 64-character SHA-256 hash.
