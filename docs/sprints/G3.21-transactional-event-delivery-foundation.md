# G3.21 — Transactional Event Delivery Foundation

**Status:** Accepted and squash-merged in PR #52 as `af48522`

**Accepted base:** `c0db6c8`

**Architecture authority:** ADR-001, ADR-004, ADR-005, ADR-006, ADR-008, and accepted ADR-013

## Objective

Create the smallest durable, tenant-safe event-delivery foundation required
before inventory analytics, notifications, or asynchronous workflows.

## Five bounded work items

1. Freeze the outbox, retry, lease, dead-letter, and inbox contract in ADR-013.
2. Add reproducible `OutboxEvent` and `EventInboxReceipt` schema and migration.
3. Add a validated transactional append primitive that reuses the shared event
   envelope.
4. Add bounded concurrent claiming, lease-safe completion, and coded retry or
   dead-letter transitions.
5. Add transactional consumer deduplication, tests, and governance evidence.

## In scope

- tenant-user and tenant-system event attribution;
- immutable event envelope with bounded JSON payload;
- at-least-once relay coordination using stable event IDs;
- bounded exponential retry and durable dead-letter state;
- serializable inbox receipt plus consumer operation;
- migration, drift, TypeScript, lint, test, and build evidence.

## Out of scope

- Kafka, Redis Streams, cloud queues, webhooks, email, SMS, WhatsApp, or push;
- notification templates, consent preferences, analytics projections, or UI;
- direct network delivery from a database transaction;
- exactly-once claims, replay authority, or dead-letter mutation APIs;
- patient or clinical payloads, controlled medicines, supplier returns, recall,
  or quarantine release;
- production deployment or compliance approval.

## Acceptance criteria

1. Empty PostgreSQL 16 migration and schema drift checks pass.
2. Cross-tenant membership and inbox references fail at the database boundary.
3. Envelope identity and payload fields cannot be updated or deleted.
4. Concurrent claims cannot lease the same row simultaneously.
5. A stale or incorrect lease cannot mark delivery or failure.
6. Retry is bounded; maximum attempts move an event to `DEAD_LETTER`.
7. Duplicate `(consumerName, eventId)` delivery cannot run the effect twice.
8. `pnpm lint`, `pnpm test`, and `pnpm build` pass on the exact head.

## Completion boundary

Passing this sprint proves only durable delivery primitives. It does not prove
that an inventory mutation emits an event, a provider received one, or that
notifications and analytics are implemented.
