# G3.18 Sprint Contract: Assigned-Provider Expiry Worklist

**Status:** Implemented; exact-head CI and CTO acceptance required

## Objective

Expose a bounded, read-only worklist of physical medicine batches approaching
expiry for one provider assigned to the active membership.

## Accepted boundary

`GET /inventory/providers/:providerId/expiry-worklist`:

1. requires `inventory.stock.read` and an active same-tenant provider assignment;
2. accepts only a 1–365 day horizon and bounded pagination;
3. returns undeleted `ACTIVE` batches with positive on-hand quantity whose
   expiry is after the server observation time and no later than the horizon;
4. excludes inactive/deleted products and deleted listings/batches;
5. orders by expiry timestamp and batch UUID for deterministic pagination;
6. returns server `asOf` and `horizonEndsAt` timestamps plus exact physical,
   held, and derived available quantities; and
7. uses a private no-store response and conceals unassigned providers as 404.

## Explicit exclusions

- expiry reconciliation, quarantine, release, recall, disposal, transfer,
  return, refund, adjustment, or any other mutation;
- risk scoring, alerts, notifications, forecasts, analytics, or policy claims;
- patient, prescription, clinical, supplier, payment, or delivery data; and
- schema, migration, permission-catalogue, audit, or worker changes.

## Acceptance evidence

Acceptance requires DTO boundary tests, route metadata tests, service unit
tests, real PostgreSQL horizon/status/assignment isolation tests with zero
infrastructure skips in CI, formatting, lint, full tests, build, database gates,
exact-head CI, and synchronized governance records.
