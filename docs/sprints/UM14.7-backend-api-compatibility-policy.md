# UM14.7 — Backend/API Compatibility Policy

## Goal

Allow a controlled, bounded overlap between old and new AIM clients during a rollout without treating compatibility metadata as trust or keeping obsolete clients alive indefinitely.

## Safety invariants

1. API generations are positive bounded integers; Git SHAs and arbitrary version strings are not ordered compatibility versions.
2. The server owns an inclusive minimum/maximum supported API-generation window.
3. A valid client inside the window may continue during rollout, preserving old/new overlap.
4. Missing, malformed, stale or future generations fail explicitly with HTTP 426.
5. Missing, malformed or reversed server policy fails closed with HTTP 503.
6. Compatibility metadata never grants identity, tenancy, provider, permission, subscription or clinical authority.
7. Authentication, authorization, organization isolation, audit and healthcare workflow validation remain independently mandatory.
8. Compatibility responses expose no vulnerability detail, patient data or organization-sensitive data.
9. The policy is bounded rollout compatibility, not an indefinite promise to support every historical client.
10. Any intentional incompatible transition must raise the minimum only after the applicable release, update and operational gates are satisfied.

## Implementation boundary

UM14.7 introduces the reusable compatibility-policy primitive and certification tests. Individual BFF/backend surfaces may consume it only at their established request boundary; they must not bypass existing auth or tenant checks. Native-store publication remains governed by UM14.6. Database/data compatibility remains UM14.8.

## Completion criteria

- overlap window accepts minimum, intermediate and maximum generations;
- unsupported clients receive 426;
- malformed server policy receives 503;
- compatibility headers are no-store and contain only bounded generation metadata;
- unit tests, lint and build pass;
- Task 0060 and applicable production-runtime/release gates pass on the exact PR head;
- PR is mergeable and merged into the authoritative branch before UM14.8 begins.
