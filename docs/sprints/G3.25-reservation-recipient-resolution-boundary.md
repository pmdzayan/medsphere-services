# G3.25 — Reservation Recipient Resolution Boundary

**Status:** Implementation in progress

**Repository baseline:** `fd8953b149ee71f901ef8b72fbb1638f421830d9`

**Architecture authority:** ADR-003, ADR-004, ADR-015, ADR-016, and proposed
ADR-017

## Objective

Resolve the opaque tenant-membership recipient created by G3.24 into one
transient email destination using authoritative same-tenant state, while
preserving the G3.23 minimal-data and fail-closed delivery boundary.

## In scope

- `TENANT_MEMBERSHIP` recipient resolution for `EMAIL` only;
- same-tenant membership lookup by opaque membership ID;
- active tenant, active membership, and active user eligibility checks;
- explicit coded unavailable, disabled, unsupported, malformed-reference, and
  invalid-destination outcomes;
- transient destination return to the existing provider-neutral worker;
- module wiring that replaces the unconfigured recipient resolver only;
- unit tests for bounded contract behavior and privacy-safe errors; and
- real PostgreSQL tests for tenant isolation, missing/stale/disabled recipients,
  account/tenant status, and concurrent deterministic resolution.

## Out of scope

- SMS, WhatsApp, push, or operational-route resolution;
- generalized recipient directories or contact synchronization;
- communication-preference or consent policy not already accepted;
- template composition or localization;
- real provider adapters, credentials, or external calls;
- changes to the G3.24 domain event or durable notification payload;
- new public or operational HTTP endpoints;
- Maps, FHIR, ABDM, Blood Bank, billing, returns, recall, quarantine release,
  patient self-service reservation creation, production deployment, or real
  healthcare data.

## Acceptance criteria

1. The resolver accepts only `TENANT_MEMBERSHIP` plus `EMAIL` and fails closed
   for every other type or channel.
2. The database lookup constrains both membership ID and tenant ID so a
   cross-tenant reference is indistinguishable from a missing reference.
3. Only active, non-ended, non-deleted membership under an active non-deleted
   tenant and active non-deleted user resolves.
4. The database query selects no names, phone numbers, reservation data,
   clinical data, or unrelated privacy/profile fields.
5. The resolved email is returned only transiently and never persisted or
   emitted through logs, metrics, queue rows, attempt evidence, or errors.
6. Repeated and concurrent valid resolution is deterministic and produces no
   database mutation.
7. The provider registry remains fail closed; G3.25 does not claim real email
   delivery.
8. Formatting, lint, architecture checks, unit tests, PostgreSQL infrastructure
   tests, production build, clean migration/drift, populated upgrade, and
   exact-head GitHub CI pass before acceptance.

## Completion meaning

Passing G3.25 proves only authorized just-in-time recipient resolution for the
first reservation-ready email workflow. It does not prove template composition,
provider delivery, communication preferences, or production notification
operation.
