# F0.10 Sprint Report: Tenant Audit-Event Workspace

**Status:** Implemented and locally verified on `cto/frontend-foundation`

**Dependency:** F0.9 effective-permission UI and the accepted S0.4 tenant-safe
authorization and durable-audit contract

## Objective

Expose the accepted tenant audit-event read model through a premium, responsive
frontend without weakening tenant isolation, permission enforcement, metadata
redaction, or append-only evidence semantics.

## Delivered

- Added an authenticated `/audit` workspace and application-shell navigation.
- Added a same-origin `GET /api/audit/events` BFF boundary that forwards only the
  accepted audit filter vocabulary. Browser-supplied tenant identifiers are
  ignored.
- Preserved the backend `audit.events.read` permission guard as the authority.
  A denied membership receives a dedicated restricted-access state and no audit
  evidence.
- Added strict frontend validation for event types, outcomes, UUIDs, timestamps,
  bounded scalar metadata, and the exact event-specific metadata-key catalogue.
- Added server-side filtering for event type, outcome, time range, actor
  membership, and complete resource type/identifier pairs.
- Added cursor-based loading of older evidence with duplicate protection.
- Added a read-only evidence detail panel for the event, actor, resource,
  request, occurrence time, and reviewed metadata.
- Added honest current-page metrics. They do not claim tenant-wide analytics.
- Kept audit export, editing, deletion, and retention management out of scope
  because the accepted API does not support those operations.

## API and security boundary

| Method | Route               | Boundary                                        |
| ------ | ------------------- | ----------------------------------------------- |
| `GET`  | `/api/audit/events` | HTTP-only access credential and query allowlist |
| `GET`  | `/audit/events`     | Authenticated tenant plus `audit.events.read`   |

- The authenticated tenant is taken only from the verified backend identity.
- The BFF never forwards a browser-provided tenant, membership authority, or
  credential.
- Successful upstream payloads fail closed when their shape, event vocabulary,
  cursor, timestamp, or metadata does not match the accepted contract.
- Responses use `Cache-Control: no-store`.
- No database schema or migration change is required.
