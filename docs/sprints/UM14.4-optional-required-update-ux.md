# UM14.4 — Optional-versus-Required Web Update UX

**Milestone:** 14 — Application Versioning & Update Management  
**Branch:** `cto/um14-4-optional-required-update-ux`  
**Dependency:** UM14.3 / PR #176 accepted and merged

## Objective

Extend the accepted UM14.3 web/PWA update flow so routine releases remain deferable while explicitly required security or incompatible releases remove the normal defer action, without exposing sensitive vulnerability information or claiming UM14.5 server-side enforcement.

## Reuse

- UM14.3 generated `sw-release.js`
- UM14.3 waiting-worker lifecycle and explicit `SKIP_WAITING`
- UM14.3 reload-after-`controllerchange` rule
- Task 0059 static-only PWA cache/privacy boundary
- existing English/Tamil/Urdu workstation localization

## Deliverables

- bounded `optional|required` release mode;
- bounded `routine|security|incompatible` reason;
- fail-fast generator validation for contradictory policy;
- waiting-worker release-policy message exchange;
- temporary no-defer state while release policy is unresolved;
- deferable optional update UX;
- persistent non-deferable required update UX;
- localized required/security/incompatible messaging;
- unit and boundary tests;
- ADR-037 and operator runbook;
- roadmap refinement.

## Out of scope

- minimum-supported-client/version rejection;
- server-side client blocking;
- native app-store mandatory update flow;
- token/session invalidation;
- per-tenant/per-region update policy;
- detailed vulnerability disclosure;
- automatic worker activation or forced reload.

## Completion criteria

1. Routine releases default to optional/routine.
2. Required mode requires an explicit bounded reason.
3. `required/routine` is rejected.
4. `optional/incompatible` is rejected.
5. Generated marker contains release identity/mode/reason only.
6. Waiting worker exposes bounded release policy through a dedicated message port.
7. The **Later** action is available only for resolved optional policy.
8. Required security/incompatible releases present localized non-deferable UX.
9. Policy-resolution timeout preserves compatibility with legacy workers.
10. Update activation remains explicit and reload remains controller-change driven.
11. Task 0059 cache/privacy boundaries remain unchanged.
12. Web tests, architecture checks, lint and build pass.
13. Exact-head Task 0060 and normal repository CI are green before merge.
