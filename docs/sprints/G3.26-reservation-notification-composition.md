# G3.26 — Reservation Notification Composition / Template Contract

**Status:** Implementation in progress

**Repository baseline:** `ba38365863df25d972f049f8d7b30a45dfa6a615`

**Architecture authority:** ADR-015, ADR-016, ADR-017, and proposed ADR-018

## Objective

Define the first deterministic, privacy-minimal composition contract for the
accepted reservation-ready notification workflow without creating a general
template engine or activating a real provider.

## In scope

- exact `reservation-ready` template key and version 1;
- exact structured variable contract `{ status: 'READY' }`;
- explicit default locale `en` and fail-closed unsupported locale behavior;
- deterministic channel-neutral subject/body output;
- bounded privacy-safe metadata;
- coded failures that never echo rejected values;
- contract, snapshot, and focused unit tests.

## Out of scope

- arbitrary free text or user-authored content;
- medicine, patient, prescription, diagnosis, clinical, contact, provider, or
  reservation details;
- multiple locales or translation infrastructure;
- provider-specific rendering;
- real provider adapters or external delivery;
- G3.27 end-to-end workflow wiring;
- Maps, FHIR, ABDM, Blood Bank, billing, returns, recall, quarantine release,
  production deployment, or real healthcare data.

## Acceptance criteria

1. Only `reservation-ready` version 1 is accepted.
2. Only `{ status: 'READY' }` is accepted as variables.
3. Unexpected, sensitive, nested, or free-text variables fail closed.
4. Output is deterministic and channel-neutral.
5. Locale defaults explicitly to `en`; unsupported locale fails closed.
6. Failures are coded and do not echo rejected content.
7. No database or provider behavior is added.
8. Formatting, lint, architecture checks, tests, build, and exact-head GitHub CI
   pass before acceptance.

## Completion meaning

Passing G3.26 proves only the bounded reservation notification composition
contract. It does not prove end-to-end delivery, retries across the whole
workflow, operational readiness, real provider delivery, or production
approval.
