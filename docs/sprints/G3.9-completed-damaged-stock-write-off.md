previously confirmed damaged quantity from one exact batch. Preserve batch,
ledger, held-stock, tenant, provider, idempotency, and audit integrity without

## Accepted HTTP boundary

Add one command to the existing Inventory controller:

`POST /inventory/providers/{providerId}/batches/{batchId}/damage`

Body:

- `expectedVersion`: positive database-safe integer;
- `quantity`: positive database-safe integer;
- `idempotencyKey`: trimmed 1–120 characters; and
- `reason`: required trimmed 1–500 character non-clinical explanation.

Return only server-derived provider, inventory, product, batch and movement
identifiers; quantity; on-hand before/after; resulting batch version; database
occurrence time; and `replayed`.

Reject unknown properties. Never accept tenant, membership, user, role,
permission, inventory, product, movement, actor, status, token, price, held,
received, before/after, timestamp, or audit authority.

Require `inventory.stock.damage`, authentication, private/no-store, safe
Swagger responses, and the accepted error envelope.

## Database contract

Add one forward-only migration that:

1. creates migration-owned `inventory.stock.damage` and grants it to active
   system tenant-administrator roles using the immutable-permission procedure;
2. adds nullable positive `StockMovement.resultingBatchVersion` without
   rewriting accepted history;
3. constrains each movement carrying the new `inventory.stock.damage`
   reference to be `DAMAGED` and carry the resulting version, command hash,
   negative delta, and tenant-user actor, without invalidating legacy rows; and
4. extends the database audit-event allowlist for
   `inventory.stock.damaged`.

Synchronize Prisma and application audit/permission allowlists. Do not edit
accepted migrations or create damage status/tables when the append-only
movement is the accepted fact.

## Atomic behavior

In one serializable transaction with bounded retry:

1. verify live provider assignment before replay lookup;
2. return exact replay or reject same-key/different-hash;
3. capture one database timestamp;
4. resolve one same-tenant/provider active, undeleted, unexpired batch/listing
   at expected version;
5. require quantity not to exceed on-hand minus held;
6. conditionally decrement on-hand only, preserve held/received, increment
   version, and exhaust only when on-hand and held both reach zero;
7. append one reconciled `DAMAGED` movement with immutable result snapshot and
   bounded reason; and
8. append one tenant-user audit with only accepted metadata.

Any authorization, validation, version, stock, movement, or audit failure rolls
back everything. Never clamp, partially commit, or consume held units. Revoked
access conceals prior receipts.

## Security and privacy

- Identity comes only from `AuthenticatedIdentity`.
- Provider assignment and permission remain server-authoritative.
- Reason is bounded, non-clinical, and absent from audit/logs.
- No patient, prescription, clinical, supplier, credential, token, payment,
  controlled-medicine, attachment, or disposal data.
- Preserve authentication, authorization-denial audit, request IDs, throttling,
  private/no-store, Helmet, safe errors, and logging policy.
