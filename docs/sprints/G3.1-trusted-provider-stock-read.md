# G3.1 Sprint Contract: Trusted Provider Stock Read

**Status:** Implementation complete; exact-commit CI and review acceptance pending

**Branch:** `cto/gate3-trusted-provider-scope`

**Accepted base:** `410368cda73fc151b04996d547b62db22231a9e8`

## Objective

Create the first accepted Gate 3 HTTP boundary: migration-backed provider access
assignments and a bounded, authenticated, permission-protected inventory stock
read model. Close the provider-authority gap without mounting stock mutations or
patient reservation routes.

## In scope

- `MembershipProviderAccess` schema, constraints, indexes, migration, and
  administrator backfill.
- Migration-owned provider-access and inventory-read permissions.
- Provider-access list, add, and remove administration routes.
- Read-only provider inventory endpoint with stable pagination and allow-listed
  search.
- Trusted tenant and membership context, provider-assignment enforcement,
  Swagger DTOs, private no-store responses, and durable mutation audit events.
- Unit, HTTP-boundary, and PostgreSQL integration coverage.
- Gates 1–9 evidence report and repository status synchronization.

## Out of scope

- Inventory configuration, receipt, adjustment, transfer, return, damage,
  expiry, reservation, fulfilment, or dispensing HTTP mutations.
- Patient self-service, marketplace, supplier, payment, delivery, or controlled
  medicine behavior.
- Gate 2 or Gates 4–9 implementation.
- Production deployment or compliance approval.

## Acceptance criteria

1. Cross-tenant membership/provider assignments are rejected by PostgreSQL.
2. Existing tenant administrators receive access only to providers in their own
   tenant during migration.
3. Provider-access mutations require explicit permissions and write atomic audit
   evidence.
4. Inventory reads require `inventory.stock.read`, trusted membership identity,
   and a live provider assignment.
5. The stock response derives available quantity from eligible batches and
   never accepts tenant or actor identifiers from the client.
6. Collections are bounded and deterministically ordered; unknown query fields
   are rejected by the shared validation boundary.
7. Formatting, lint, tests, build, migration deployment, and drift verification
   pass.
