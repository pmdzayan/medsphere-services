# UM14.1 — Blue/Green Environment & Role Model

**Milestone:** 14 — Application Versioning & Update Management  
**Branch:** `cto/um14-1-blue-green-environment-role-model`  
**Base:** `feature/database-architecture`

## Objective

Create the smallest architecture-consistent blue/green foundation that lets AIM reuse the inactive environment for the next update without hard-coding a permanent live database.

## Reuse

UM14.1 reuses:

- Task 0022 backup/restore/recovery controls;
- Task 0023 production runtime and deployment safety;
- Task 0050 exact-artifact release certification and rollback boundary;
- Task 0058 measure-before-complexity governance;
- Task 0060 independent high-risk change controls.

It does not introduce a new datastore, deployer, migration engine or traffic controller.

## Deliverables

- Accepted ADR-033.
- Executable BLUE/GREEN role policy.
- State and transition validator with fail-closed CLI.
- Unit tests for split-brain prevention, synchronization evidence, candidate promotion and direct rollback-swap rejection.
- Binding Project Rules section.
- Roadmap and production-runbook integration.

## Explicitly out of scope

- database copy/restore automation;
- logical/physical replication activation;
- production credentials or provider configuration;
- schema expand/contract enforcement;
- shadow traffic;
- 5%/10%/25%/50%/100% canary routing;
- automatic rollback;
- real production deployment.

## Completion criteria

1. Exactly one ACTIVE environment is enforced.
2. Write authority equals ACTIVE.
3. Candidate synchronization evidence is required and bound to the ACTIVE release.
4. Direct ROLLBACK-to-ACTIVE transitions fail.
5. Candidate promotion preserves the former ACTIVE as ROLLBACK.
6. BLUE/GREEN database identities remain stable while roles rotate.
7. No secret-bearing database URLs are accepted as database identities.
8. Focused tests and the mandatory architecture gate pass.
9. Normal `pnpm lint`, `pnpm test`, and `pnpm build` must pass before merge.
