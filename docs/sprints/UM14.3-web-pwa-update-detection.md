# UM14.3 — Web/PWA Update Detection & Safe Update Flow

**Milestone:** 14 — Application Versioning & Update Management  
**Branch:** `cto/um14-3-web-pwa-update-detection`  
**Stacked dependency:** UM14.2 / PR #173

## Objective

Make every new AIM frontend build reliably discoverable by an already-open web/PWA client while ensuring activation never reloads operational healthcare work without explicit user action.

## Reuse

- Task 0048 PWA runtime and service-worker registration.
- Task 0059 static-only Cache Storage and no-cache service-worker headers.
- Task 0023 bounded non-secret release identity.
- Existing language system for English/Tamil/Urdu update UI.
- Existing `SKIP_WAITING` explicit-activation protocol.

## Deliverables

- deterministic non-secret web release marker generator;
- release marker imported by the service worker and incorporated into public cache generation;
- bounded update checks on startup/reconnect/visibility/focus/interval;
- explicit localized **Update now** / **Later** UI;
- reload only after `controllerchange`;
- unit tests for marker generation and update-check throttling;
- Task 0059/PWA boundary tests for release-marker import and no-cache headers;
- ADR-036, operations documentation and roadmap refinement.

## Out of scope

- forced/mandatory security update UX;
- minimum-supported-client rejection;
- native Google Play/App Store update flow;
- backend/API compatibility policy;
- database migration compatibility;
- canary traffic routing;
- automatic rollback.

## Completion criteria

1. A frontend-only build changes the service-worker script graph.
2. The marker contains no secrets or healthcare data.
3. Existing clients perform bounded update discovery.
4. Offline clients do not poll.
5. New worker activation requires explicit user action.
6. Reload happens only after `controllerchange`.
7. Update UI is localized in all currently complete UI languages.
8. `sw.js` and `sw-release.js` remain no-cache.
9. Task 0059 static-only healthcare cache boundary remains intact.
10. Web tests, architecture tests, network boundary, lint and build pass.
