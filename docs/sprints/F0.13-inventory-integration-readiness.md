# F0.13 Sprint Contract: Inventory Integration Readiness

**Status:** Completed and locally verified; review pending

**Branch:** `cto/frontend-task13`

**Accepted base:** `410368cda73fc151b04996d547b62db22231a9e8`

**Dependency:** PR #10 accepted and squash-merged; ADR-005 inventory HTTP
boundary remains unmounted

## Objective

Make the premium inventory workspace truthful and ready to receive an accepted
read contract later. Separate its sanitised preview dataset from presentation,
derive every displayed count and value from that dataset, and prove inventory
quantity invariants without inventing a live API or enabling mutations.

## Repository findings

1. The inventory workspace imports a module-level sample array directly.
2. Status tabs and categories are also derived from that hidden global.
3. Headline metrics claim totals such as 1,254 products and ₹24.8 lakh even
   though the page displays only eight sanitised sample batches.
4. Import, receipt, scanner, row action, and mutation controls are correctly
   disabled because no accepted production inventory HTTP controller exists.
5. ADR-005 requires batch-authoritative quantities, where available stock is
   `onHand - held`; the preview model currently names held quantity `reserved`.

## In scope

- Introduce an explicit serialisable preview dataset contract.
- Use `held` terminology consistent with ADR-005.
- Validate preview quantity invariants at the data boundary.
- Derive summary metrics, status counts, filters, and categories from the
  supplied dataset.
- Render an accessible, unmistakable preview-source disclosure.
- Add unit and component tests covering invariant rejection, derived metrics,
  filtering, and honest preview rendering.
- Synchronize roadmap, status, and handoff documents with PR #10 acceptance and
  this frontend checkpoint.

## Out of scope

- Inventory BFF or backend endpoints.
- Authentication, permission, provider, tenant, or actor contract changes.
- Stock receipt, adjustment, import, reservation, or dispensing mutations.
- Public patient reservations, marketplace, supplier, delivery, payment, or
  controlled-medicine behavior.
- Treating preview data as operational evidence.

## Acceptance criteria

1. The workspace receives its dataset explicitly and does not import hidden
   sample state.
2. Every metric, tab count, category, row, and filter result comes from the
   same supplied dataset.
3. The data boundary rejects negative quantities, held quantities above
   on-hand, incorrect available quantities, invalid prices, duplicate IDs, and
   duplicate batch identities.
4. The interface labels the dataset as sanitised preview data and keeps every
   unsupported mutation disabled.
5. No network request, route, permission, database change, or backend contract
   is added.
6. Formatting, lint, tests, and production build pass.

## Next dependency

The backend inventory HTTP-contract sprint must define and accept the tenant,
provider, permission, pagination, filtering, error, Swagger, and audit boundary
before a later frontend sprint adds live fetching.
