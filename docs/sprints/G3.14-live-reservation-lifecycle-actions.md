# G3.14 Sprint Contract: Live Reservation Lifecycle Actions

**Status:** Accepted and squash-merged in PR #43 as `7feacbb` after exact-head
CI run `31763879935` passed all required gates.

**Accepted implementation base:** `636eb86530aa4bac7813f71f6d107252fba05d09`

## Objective

Connect the accepted G3.3 assigned-provider staff transitions to the G3.5 live
reservation workspace without exposing patient identity or weakening lifecycle,
stock, concurrency, idempotency, assignment, permission, or audit controls.

## In scope

- exact request and receipt contracts for `CONFIRM`, `READY`, `COMPLETE`, and
  `CANCEL` only;
- one same-origin authenticated private no-store BFF route;
- state-derived actions using the live reservation version;
- explicit confirmation, with irreversible stock effects disclosed for complete
  and cancel;
- one stable idempotency key per open confirmation;
- authoritative list refresh and bounded receipt evidence after success; and
- contract, BFF, API-client, success, refresh, and conflict tests.

## Safety boundary

The backend remains authoritative for provider assignment, manage permission,
state, expiry, version, allocations, stock consumption or release, transaction,
idempotency, and audit. This sprint adds no `EXPIRE`, reservation creation,
patient identity, prescription, payment, delivery, controlled-medicine, partial
fulfilment, or reversal behavior.

## Acceptance gate

Formatting, lint, tests, build, dependency audit, clean and populated database
verification, exact-head CI, and CTO review must all pass before acceptance.
