# UM14.5 — Minimum-Supported Client Enforcement

**Milestone:** 14 — Application Versioning & Update Management  
**Branch:** `cto/um14-5-minimum-supported-client-enforcement`  
**Dependency:** UM14.4 / PR #177 accepted and merged

## Objective

Add server-authoritative minimum web-client enforcement so a known-incompatible stale browser does not silently continue to use AIM APIs after the accepted minimum client generation advances.

## Reuse

- UM14.3 release marker and update discovery;
- UM14.4 bounded release policy;
- existing Next BFF boundary;
- Fetch Metadata browser signals;
- existing no-store response practices.

## Deliverables

- bounded monotonic web client generation;
- generated browser compatibility cookie before hydration;
- bounded minimum-generation runtime policy;
- Next middleware on browser BFF API traffic;
- HTTP 426 for missing/invalid/outdated browser generation;
- fail-closed 503 for malformed server policy;
- unit tests for generation parsing and compatibility evaluation;
- middleware tests for 426/503/allow paths;
- ADR-038 and operator runbook;
- roadmap refinement.

## Out of scope

- native Android/iOS minimum version;
- app-store routing;
- signed client attestation;
- auth or tenant authorization through client version;
- per-region or per-tenant minima;
- backend/API overlap policy beyond the minimum gate;
- rollout percentages and feature flags.

## Completion criteria

1. Git SHA is never treated as an ordered version.
2. Client generation is bounded, positive and monotonic by release policy.
3. Current web build exposes generation through the accepted release marker.
4. Browser receives generation before normal application hydration.
5. Browser API request without valid generation fails with 426.
6. Browser API request below minimum fails with 426.
7. Supported browser generation continues normally.
8. Malformed server minimum policy fails closed with 503.
9. Compatibility metadata is never used for authentication or authorization.
10. Responses expose no sensitive vulnerability or healthcare detail.
11. Existing UM14.3/UM14.4 behavior remains intact.
12. Tests, lint, formatting, build, exact-head CI and Task 0060 are green before merge.
