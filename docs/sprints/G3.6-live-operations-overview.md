# G3.6 Sprint Contract: Live Operations Overview

**Status:** Accepted; exact-head workflow `31305222063`; squash-merged in PR #23

**Accepted base:** `6c68ee324f6bf6f003413ef390b5710ea7029b1a`

## Objective

Remove the dashboard's fabricated pharmacy metrics, patient names, stock-risk
claims, and activity feed. Replace them with a bounded overview composed only
from the accepted G3.4 stock and G3.5 reservation read boundaries.

## Accepted dependencies

- `GET /api/inventory/providers`;
- `GET /api/inventory/stock`;
- `GET /api/inventory/reservations`;
- G3.4 and G3.5 exact response validation, authentication refresh, provider
  assignment enforcement, and private no-store behavior.

## Accepted scope

- select an active provider assigned to the authenticated membership;
- load a bounded first page of stock and reservations for that provider;
- show clearly labelled current-page product, batch, on-hand, held, available,
  reservation, status, and medicine-unit counts;
- show bounded recent reservation and stock rows using only accepted fields;
- link to the complete Inventory and Reservations workspaces;
- handle provider, stock, and reservation loading/errors independently so one
  denied or unavailable read does not fabricate or conceal the other;
- provide empty-assignment, empty-data, restricted, unavailable, and retry
  states;
- keep the page read-only and responsive.

## Explicitly blocked

- inventory valuation, trend, percentage change, stock-health percentage,
  low-stock, reorder, criticality, days-of-cover, cold-chain, expiry-risk, or
  operational-priority claims;
- patient name/initials, pickup timing, prescription, payment, delivery, or
  clinical data;
- fabricated activity, goods-receipt, fulfilment, alert, or analytics events;
- receive-stock, create-reservation, reservation-transition, or other mutation
  controls;
- tenant-wide totals inferred from a bounded page;
- a new upstream endpoint, database change, permission, analytics policy, or
  API-gateway composition decision.

## Composition contract

The overview reuses the accepted same-origin BFF routes. It does not add a
dashboard aggregation endpoint. After provider selection it requests bounded
stock and reservation pages independently, with `limit <= 10` and `offset = 0`.

All calculated values must be labelled **current page**. The UI must not convert
the upstream `total` pagination count into a medicine-unit, valuation, risk, or
tenant-wide operational metric. A list's upstream `total` may be shown only as
its exact product/reservation result count.

## Security and privacy behavior

- Browser code never receives or supplies trusted membership, tenant, role,
  permission, or access-token identity.
- Backend provider assignment and permission checks remain authoritative for
  each independent request.
- No patient or prescription identity is rendered.
- No mutation control is present or enabled.
- Existing BFF `private, no-store` behavior remains unchanged.

## Completion criteria

1. Dashboard tests prove assigned-provider selection and independent stock and
   reservation reads.
2. Tests prove current-page metrics, accepted rows, partial failure, empty
   assignment/data, and retry states.
3. Tests prove removal of every fabricated metric, patient name, risk claim,
   activity item, and mutation control in the current dashboard.
4. Inventory and Reservations links are accessible on desktop and mobile.
5. No backend, database, permission, or API-gateway behavior changes.
6. Repository formatting, lint, tests, build, and production dependency audit
   pass.
7. Exact-commit pull-request CI, review, and merge acceptance pass.

G3.6 is a truthfulness and composition checkpoint, not an analytics milestone
or completion of Gate 3.
