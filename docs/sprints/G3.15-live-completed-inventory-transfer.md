# G3.15 Sprint Contract: Live Completed Inventory Transfer

**Status:** Implemented locally; exact-head CI and CTO acceptance required.

**Accepted implementation base:** `7feacbb6b98addde021fef5ff2afb446fd870e2d`

## Objective

Connect the accepted G3.8 completed physical transfer command to the live
assigned-provider stock workspace without inventing shipment or transit state.

## In scope

- exact completed-transfer request and correlated receipt contracts;
- one authenticated same-origin private no-store BFF route;
- destination selection from other assigned providers only;
- source quantity bounded to currently available stock and source batch version;
- explicit confirmation that physical movement already occurred;
- stable idempotency, optional trimmed bounded operational reason, authoritative
  source refresh, and bounded receipt evidence; and
- contract, BFF, API-client, success, refresh, and invalid-quantity tests.

## Safety boundary

The backend remains authoritative for dual provider assignment, permission,
destination listing, source eligibility, provenance, quantity, version, both
stock updates, ledger movements, transaction, idempotency, and audit. No
dispatch, shipment, transit, receipt, approval, reversal, patient, supplier,
payment, delivery, or controlled-medicine workflow is added.

## Acceptance gate

Formatting, lint, tests, build, dependency audit, clean and populated database
verification, exact-head CI, and CTO review must pass before acceptance.
