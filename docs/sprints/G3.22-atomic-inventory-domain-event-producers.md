# G3.22 — Atomic Inventory Domain Event Producers

**Status:** Accepted and squash-merged in PR #54 as `3e7a8c0`

**Accepted base:** `56ca961cddd7a00b64ceea335deca0616cdd967c`

**Architecture authority:** ADR-004, ADR-005, ADR-007 through ADR-013, and
accepted ADR-014

## Objective

Use the accepted transactional event-delivery foundation by atomically emitting
minimal versioned events from already accepted inventory workflows.

## Five bounded work items

1. Freeze the producer catalogue, attribution, privacy, versioning, and
   transaction contract in ADR-014.
2. Add atomic reservation creation and staff lifecycle producers.
3. Add atomic reservation-expiry, batch-expiry, and quarantine producers.
4. Add atomic damaged-stock and completed-transfer producers.
5. Add unit, PostgreSQL rollback/persistence, documentation, and exact-head CI
   evidence.

## In scope

- the ten version-1 event types listed in ADR-014;
- tenant-user and fixed tenant-system attribution;
- same-transaction state, receipt or movement, audit, and outbox persistence;
- replay suppression through existing command idempotency boundaries;
- minimum operational payloads without subject/contact/free-text data;
- unit and PostgreSQL integration evidence.

## Out of scope

- notification templates, preferences, recipient lookup, email, SMS, WhatsApp,
  push, webhooks, or provider credentials;
- analytics projections, broker deployment, relay scheduling, or replay UI;
- patient-facing reservation creation or exposure;
- ABDM, FHIR, Maps, RxNorm, openFDA, payment, or any external API;
- quarantine release, recall, returns, disposal, controlled medicines, or real
  healthcare data;
- production or compliance approval.

## Acceptance criteria

1. Each accepted target transition appends the allowlisted version-1 event in
   its authoritative serializable transaction.
2. Replays and rejected mutations append no duplicate event.
3. Tenant-user and tenant-system attribution comes from trusted context.
4. Payloads contain no subject identity, contact data, free text, request data,
   credentials, or clinical content.
5. A forced outbox failure rolls back state, movement or receipt, and audit.
6. PostgreSQL integration evidence confirms the persisted envelope and payload.
7. `pnpm format:check`, `pnpm lint`, `pnpm test`, and `pnpm build` pass on the
   exact review head.

## Completion boundary

Passing this sprint proves atomic production into the durable outbox only. It
does not prove relay deployment, recipient resolution, notification delivery,
analytics, external API integration, production readiness, or approval for real
healthcare data.
